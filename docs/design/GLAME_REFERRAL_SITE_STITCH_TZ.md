# GLAME Referral Site — ТЗ для Stitch

Дата: 2026-06-27  
Назначение: подготовить Stitch к сборке дизайна и интерактивного прототипа реферального сайта GLAME, связанного с основной платформой GLAME и ее API.

Домен: `partner.glamejewelry.ru`  
Контакт партнерской программы: `partner@glamejewelry.ru`

---

## 1. Роль Stitch

Stitch должен собрать не промо-лендинг, а рабочий продуктовый интерфейс реферальной программы:

- публичный сайт для объяснения программы и входа/регистрации;
- личный кабинет партнера со статистикой, кодом, ссылкой, рефералами, покупками, комиссиями и выплатами;
- адаптивный интерфейс для desktop и mobile;
- интерфейсные состояния для загрузки, пустых данных, ошибок API, ожидания модерации и заблокированного аккаунта;
- визуальную систему в стиле GLAME без новой айдентики;
- структуру, готовую к подключению к API основной платформы GLAME.

Stitch не должен проектировать отдельную бизнес-логику, отдельную CRM или независимую базу данных. Сайт является frontend-слоем над API GLAME.

---

## 2. Главная идея сайта

Реферальный сайт GLAME — это спокойный, премиальный кабинет партнера, который показывает:

- какой код использовать;
- сколько людей пришло по рекомендации;
- кто сделал первую покупку;
- какой оборот принесли рефералы;
- сколько комиссии начислено, подтверждено и выплачено;
- какой режим вознаграждения выбран: баллы GLAME или деньги;
- для денежного режима: создан ли контрагент в 1С, активен ли агентский договор, какие начисления уже переданы в 1С;
- для балльного режима: сколько баллов начислено и доступно;
- что нужно сделать, чтобы получить выплату.

Интерфейс должен ощущаться как финансовый/партнерский dashboard GLAME: точный, холодный, архитектурный, без маркетплейсной визуальности.

## 3. Аудитория

### 3.1. Партнер

Покупатель, стилист, партнер, блогер или постоянный клиент, который рекомендует GLAME и хочет видеть прозрачную статистику.

Ему важно:

- быстро скопировать код или ссылку;
- понять, работает ли код;
- видеть, сколько людей зарегистрировалось;
- видеть комиссии и статусы выплат;
- не разбираться в сложной бухгалтерии.

### 3.2. Потенциальный партнер

Пользователь, который еще не зарегистрирован в программе.

Ему важно:

- быстро понять условия;
- войти по телефону;
- отправить заявку;
- получить статус: активен или ожидает одобрения.

### 3.3. Администратор

В рамках этого ТЗ Stitch не делает полноценную админку, но дизайн должен предусмотреть, что данные приходят из платформы и модерируются там.

---

## 4. Связь с платформой GLAME

Сайт должен работать с основным backend API GLAME.

Базовый API URL задается конфигурацией:

```text
NEXT_PUBLIC_API_BASE_URL=https://<glame-platform-domain>/api
```

Авторизация должна использовать существующий механизм платформы:

- SMS/OTP по телефону или существующий auth token;
- хранение access token как в основной платформе;
- все закрытые страницы требуют авторизации.

Если пользователь уже авторизован в основной платформе на том же домене, сайт должен уметь переиспользовать сессию/токен.

## 6. Обязательные экраны

### 6.1. Public landing `/referral`

Цель: объяснить программу и привести пользователя к входу/регистрации.

Первый экран:

- оригинальный логотип GLAME;
- заголовок: `Реферальная программа GLAME`;
- подзаголовок: `Приглашайте клиентов и получайте комиссию с их покупок`;
- CTA: `Войти в кабинет`;
- CTA secondary: `Стать партнером`.

Блоки:

- как работает программа:
  1. Получите код.
  2. Передайте код клиенту.
  3. Клиент вводит код при первой покупке.
  4. Вы получаете комиссию с покупок.
- что видит партнер в кабинете;
- условия MVP:
  - бонус рефералу после первой покупки;
  - партнер может получать вознаграждение баллами GLAME или деньгами;
  - баллы начисляются внутри системы GLAME;
  - денежное вознаграждение доступно только для ИП или самозанятых после подписания агентского договора;
  - для денежного режима нужны паспортные данные и реквизиты;
  - партнер сам платит налоги за себя;
  - вознаграждение не начисляется с доставки и отмененных заказов;
  - денежные выплаты после проверки и агентского начисления в 1С;
- блок доверия: связь с платформой GLAME и 1С;
- блок учета: для денежного режима партнер оформляется как контрагент 1С, выплаты проходят как агентские начисления по договору;
- CTA внизу.

Важно: это не должен быть длинный кричащий маркетинговый лендинг. Он должен быть коротким, строгим и полезным.

### 6.2. Login `/referral/login`

Поля:

- телефон;
- кнопка `Получить код`;
- ссылка на правила программы.

Состояния:

- невалидный телефон;
- SMS отправлена;
- лимит отправки;
- ошибка API.

### 6.3. OTP `/referral/otp`

Поля:

- 4-6 ячеек OTP в зависимости от текущей платформы;
- таймер повторной отправки;
- кнопка `Войти`.

Состояния:

- неверный код;
- истекший код;
- loading;
- resend available.

### 6.4. Join `/referral/join`

Экран для пользователя, который авторизован, но еще не участвует в программе.

Состав:

- краткое описание условий;
- режим вознаграждения по умолчанию: `Баллы GLAME`;
- пояснение, что на регистрации выбор режима не нужен;
- создание покупателя в 1С в группе `Покупатели / Партнер-рефовод` после подключения, если у партнера заполнены ФИО и телефон;
- заблокированный информационный блок `Деньги`: доступно после достижения уровня партнера;
- чекбокс согласия с правилами;
- поля профиля, если не хватает данных:
  - ФИО;
  - телефон readonly;
  - email optional;
  - город optional;
  - способ связи optional;
- CTA: `Подключить программу`;

После отправки возможны два состояния:

- `active`: сразу перейти в dashboard;
- `pending`: перейти на `/referral/pending`.

### 6.5. Pending `/referral/pending`

Для заявки на модерации.

Состав:

- статус `Заявка на проверке`;
- что будет дальше;
- контакт партнерской программы: `partner@glamejewelry.ru`;
- кнопка `Обновить статус`.

### 6.5.1. Cash Setup `/referral/cash-setup`

Экран оформления денежного вознаграждения.

Показывать только если партнер достиг нужного уровня и нажал переход на денежное вознаграждение в кабинете.

Состав:

- status banner: `Денежное вознаграждение доступно для ИП и самозанятых`;
- выбор юридического статуса:
  - `Самозанятый`;
  - `ИП`;
- поля:
  - ФИО;
  - ИНН;
  - паспортные данные, необходимые для агентского договора;
  - платежные реквизиты;
  - email для документов;
- чекбоксы:
  - согласие на обработку персональных данных;
  - согласие с агентским договором/офертой;
  - подтверждение, что партнер самостоятельно платит налоги и отвечает за свой налоговый режим;
- состояния проверки:
  - `Нужны данные`;
  - `Данные отправлены`;
  - `Проверяем данные`;
  - `Создаем контрагента в 1С`;
  - `Оформляем агентский договор`;
  - `Договор активен`;
  - `Ошибка проверки`.

Важно: после отправки паспортные данные в UI не показывать полностью. Показывать только статус и, при необходимости, маску.

### 6.6. Dashboard `/referral/dashboard`

Главный экран личного кабинета.

Верхняя область:

- приветствие;
- статус программы: `Активен`, `На проверке`, `Заблокирован`;
- режим вознаграждения: `Баллы GLAME` или `Денежное вознаграждение`;
- для балльного режима: баланс баллов и статус начислений;
- для денежного режима: статус 1С `Контрагент создан`, `Договор активен`, `Требуются данные`, `Ошибка синхронизации`;
- реферальный код;
- кнопка копирования кода;
- реферальная ссылка;
- кнопка копирования ссылки;
- кнопка `Поделиться`;
- QR-код для передачи клиенту в магазине/соцсетях.

KPI cards:

- Регистрации;
- Активные рефералы;
- Покупки за период;
- Оборот рефералов;
- Вознаграждение в холде;
- Подтверждено;
- Начислено баллами или в 1С;
- Выплачено/зачислено за период;
- Средний чек рефералов.

График:

- линия/столбцы по дням: покупки, оборот, комиссия;
- переключатель периода: 7 дней, 30 дней, 90 дней, год.

Нижние таблицы:

- последние рефералы;
- последние покупки;
- последние комиссии.

Пустое состояние:

- если нет рефералов, показать код, ссылку, QR и короткий текст `Передайте код первому клиенту`.

Агентские начисления комиссий.

KPI сверху:

- В холде;
- Подтверждено;
- Выплачено;
- Отменено/скорректировано.

Таблица:

- дата покупки;

- ставка;
- база;
- сумма комиссии;
- статус комиссии;
- статус начисления в 1С;

Статусы:

- `pending` -> `В холде`;

Статусы 1С:

- `exporting` -> `Передается в 1С`;

- `error` -> `Ошибка 1С`;

Выплаты, балльные зачисления и закрытие агентских начислений.

Состав:

- для `Деньги`: контрагент 1С;
- для `Деньги`: агентский договор;
- для `Деньги`: реквизиты выплаты;
- история выплат.

Таблица:

- период;
- сумма;
- статус;
- документ начисления 1С;
- документ оплаты 1С;
- дата создания начисления в 1С;
- дата оплаты;
- комментарий.

Статусы:

- `draft` -> `Готовится`;
- `exported_to_1c` -> `Начислено в 1С`;
- `paid` -> `Выплачено`;

### 6.12. Rules `/referral/rules`

Страница правил.

Состав:

- кто может участвовать;

- денежное вознаграждение как апгрейд после достижения уровня партнера;

- что партнер сам платит налоги за себя;

- контакты поддержки.

## 8. Визуальная система

Использовать GLAME identity rules:

- graphite `#222426`;
- near black `#0E1012`;
- steel gray `#8E9397`;
- cold light gray `#C7CBCF`;
- white `#EFF1F2`;
- border gray `#5C6064`;
- radius `0px`;
- border `1px`;
- строгая сетка;
- без pill buttons;
- без marketplace shadows;
- без warm beige/gold luxury UI;
- без glow, bokeh, glassmorphism.

Основной визуальный характер:

- темный/графитовый кабинет с холодными светлыми панелями;
- таблицы должны быть плотными, читаемыми, рабочими;
- KPI cards не должны выглядеть как рекламные карточки;
- графики спокойные, монохромные, с одним акцентом steel/cold gray;
- кнопки прямоугольные;
- иконки только line-style, нейтральные.

Логотип:

- использовать только approved asset;
- не генерировать и не перерисовывать.

## 9. UX-правила

### 9.1. Денежные суммы

API отдает копейки, UI показывает рубли:

```text
76000 -> 760 ₽
4860000 -> 48 600 ₽
```

Формат:

```text
48 600 ₽
```

### 9.2. Проценты

`commission_rate_bps = 500` показывать как `5%`.

### 9.3. Персональные данные рефералов

Не показывать полный телефон, ФИО, email реферала.

Разрешено:

- `Анна К.`;
- `+7 *** *** 45 67`;
- внутренний короткий ID.

### 9.4. Копирование кода

После клика:

- показать состояние `Скопировано`;
- вернуть исходный текст через 1.5-2 секунды.

### 9.5. QR-код

QR-код должен вести на реферальную ссылку.

Если QR не загрузился:

- показать fallback с кодом и кнопкой копирования.

### 9.6. Empty states

Пустые состояния должны помогать действовать:

- нет рефералов: показать код/ссылку и CTA `Скопировать ссылку`;
- нет покупок: объяснить, что покупки появятся после первой подтвержденной покупки реферала;
- нет выплат: объяснить, что выплаты появятся после подтверждения комиссии.

### 9.7. Error states

Ошибки API:

- короткое сообщение;
- кнопка `Повторить`;
- без технического stack trace.

## 10. Responsive

### Mobile

Ширины: 360, 390, 430 px.

Правила:

- dashboard должен быть первым экраном, не лендингом после авторизации;
- таблицы превращаются в карточки;
- код и ссылка должны быть доступны на первом экране;
- bottom nav/drawer не должен перекрывать CTA;
- все суммы должны помещаться без обрезки;
- график можно упростить до горизонтального scroll или compact chart.

### Tablet

Ширины: 768, 834, 1024 px.

Правила:

- sidebar можно заменить compact rail;
- KPI cards 2-3 колонки;
- таблицы сохраняются таблицами.

### Desktop

Ширины: 1280, 1440, 1728 px.

Правила:

- fixed sidebar;
- top utility bar;
- content max-width 1280-1440;
- KPI cards 4 колонки;
- таблицы full-width.

## 11. Состояния участника программы

### Не авторизован

Показывать public landing и CTA входа.

### Авторизован, не участник

Показывать join screen.

### Pending

Показывать pending screen, без dashboard-данных.

### Active

Показывать полный dashboard.

Если программа активна, но контрагент или агентский договор еще создается в 1С:

- dashboard доступен;
- блок кода доступен;
- денежные выплаты показываются как недоступные до статуса договора `active`;
- в верхней области показать status banner: `Оформляем агентский договор в 1С`;
- если API вернул ошибку, показать `Нужны данные для договора` или `Ошибка синхронизации с 1С` с CTA `Связаться с поддержкой`.

Если выбран режим `Баллы GLAME`:

- не показывать блоки паспортных данных, контрагента 1С и агентского договора;
- вместо выплат показывать историю зачисления баллов;
- CTA в профиле: `Перейти на денежное вознаграждение`, который ведет на `/referral/cash-setup`.

### Blocked

Показывать ограниченный экран:

- статус `Доступ к программе ограничен`;
- причина, если API передал;
- контакт поддержки;
- таблицы и выплаты скрыты.

### Archived

Показывать read-only историю без возможности копировать активный код.

## 12. Интерактивность прототипа

Stitch должен показать кликабельные переходы:

```text
Landing -> Login -> OTP -> Join -> Dashboard
Join -> Cash Setup -> Pending -> Dashboard
Dashboard -> Referrals
Dashboard -> Purchases
Dashboard -> Commissions
Dashboard -> Payouts
Dashboard -> Profile
Profile -> Cash Setup
Dashboard -> Rules
```

В dashboard должны быть интерактивные состояния:

- смена периода;
- копирование кода;
- копирование ссылки;
- открытие QR;
- пустой список;
- список с данными.

## 13. Контент и микрокопи

Использовать спокойный, точный тон.

Примеры:

- `Ваш реферальный код`
- `Передайте код клиенту до первой покупки`
- `Комиссия появится после подтверждения покупки`
- `Покупка находится в холде до окончания периода возврата`
- `Данные синхронизируются с платформой GLAME и 1С`
- `Скопировано`
- `Пока нет активных рефералов`

Не использовать:

- агрессивные обещания заработка;
- “получай пассивный доход без усилий”;
- чрезмерно рекламные формулировки;
- финансовые обещания без статуса проверки.

---

## 14. Что не входит в задачу Stitch

Stitch не должен:

- реализовывать backend;
- проектировать структуру БД;
- менять правила начисления комиссии;
- делать админку 1С;
- создавать новый логотип или новую айдентику;
- рисовать отдельную платежную систему;
- показывать полные персональные данные рефералов.

## 15. Acceptance checklist

Дизайн считается готовым, если:

- есть все обязательные экраны;
- после авторизации главный экран является рабочим dashboard, а не лендингом;
- код, ссылка и QR доступны сразу;
- при регистрации автоматически подключается режим баллов GLAME;
- денежное вознаграждение доступно только после достижения уровня партнера;
- для балльного режима нет лишних блоков договора/паспорта;
- для денежного режима есть экран оформления: ИП/самозанятый, ИНН, паспортные данные, реквизиты, подтверждение налоговой ответственности;
- есть статистика регистраций, покупок, оборота, комиссий и выплат;
- есть таблицы/карточки рефералов, покупок, комиссий, выплат или балльных зачислений;
- все суммы и статусы читаемы на mobile и desktop;
- персональные данные рефералов замаскированы;
- предусмотрены loading, empty, error, pending, blocked states;
- API-зависимости явно отражены в структуре экранов;
- визуальный язык соответствует GLAME;
- нет warm beige/gold luxury UI, pill buttons, glow, glassmorphism, marketplace cards;
- логотип и G-знак не перерисованы;
- прототип кликабельный по основным маршрутам.
