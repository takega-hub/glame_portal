# CRM-модуль «Новое поступление»

Дата: 2026-08-21

## Назначение

Постоянная CRM-кампания «Новое поступление» создаёт персональные задачи продавцам/управляющим только по реальному первичному приходу товарного ассортимента через 1С закупки/приходные накладные на основной склад. Цель — не массовая рассылка, а релевантные касания: ответ клиента, визит, онлайн-подбор, дистанционная покупка или продажа.

## Где реализовано

- Backend-сервис: `backend/app/services/crm_new_arrival_service.py`
- API администратора: `POST /api/admin/crm/tasks/new-arrivals/generate`
- Схемы API: `backend/app/schemas/crm_tasks.py`
- Фоновый запуск: `backend/app/services/crm_touchpoint_scheduler.py`
- UI администратора: `frontend/src/components/admin/AdminCrmTasksPage.tsx`
- UI продавца: `frontend/src/components/profile/SellerCrmPage.tsx`

## Кампания

- `campaign_id`: `new-arrival-clienteling`
- `campaign_name`: `Новое поступление`
- `crm_group`: `new_arrival`
- `source`: `crm_new_arrival`

## Источник данных

Источник кампании — только подтверждённые события первичного прихода товарного ассортимента:

- `product_stock_arrival_events`

События должны писаться импортом закупки/приходной накладной 1С на основной склад. Перемещения между складами/магазинами и изменение доступного остатка в магазине не являются новым поступлением для CRM и не должны создавать записи в этой таблице.

Сохраняются `previous_available_quantity`, `available_quantity`, `delta_quantity`, `event_type`, `source_sync_id`, `received_at`.

Тип события:

- `NEW_TO_STORE` — первичный приход новой товарной позиции/коллекции на основной склад;
- `RESTOCK` — повторный закупочный приход уже известной товарной позиции на основной склад;
- `REPLENISHMENT` — технический запасной тип для прочего пополнения.

Дополнительные таблицы ассортимента и остатков используются только для карточки задачи и проверки доступности:

- `product_stocks`
- `products`
- `stores`

Polling fallback по свежим остаткам отключён. Остатки и перемещения магазинов отражают распределение и доступность, но не источник «нового поступления».

Чтобы повторные приходные события не создавали дубли CRM-задач по тем же товарам, добавлена защита: если по тем же SKU/бренду/CRM-магазину уже была задача «Новое поступление» в пределах `CRM_COMMERCIAL_COOLDOWN_DAYS`, новое поступление пропускается с причиной `arrival_cooldown_same_products`.

## Исключения ассортимента

Сопутствующие и технические позиции не считаются новым поступлением даже при наличии приходной накладной:

- пакеты;
- мешочки;
- коробки;
- футляры;
- салфетки;
- упаковочные материалы;
- расходники;
- бирки, ярлыки, наклейки, пломбы;
- сертификаты, открытки, холдеры и прочие сопутствующие материалы.

Такие позиции фильтруются общим правилом `product_eligible_filter` из `backend/app/services/sales_record_filters.py`.

## Сегментация клиентов

Приоритеты:

- `P1` — explicit interest / waitlist: клиент просил сообщить о поступлении конкретного товара.
- `P2` — brand buyer: покупал этот бренд.
- `P3` — relevant assortment: покупал релевантные категории/уровень цены.
- `P4` — VIP/high value: ценный клиент CRM-магазина, история покупок соответствует уровню поступления.
- `P5` — warm expansion: осторожное расширение, только если первых релевантных групп мало и поступление не слабое.

Для каждой задачи пишется `selection_reason` — человекочитаемое основание, почему клиент выбран. Если основания нет, задача не создаётся.

## Блокировки

Задача не создаётся, если:

- у клиента `do_not_contact` / `do_not_disturb`;
- есть открытый сервисный кейс в `crm_service_cases`;
- у клиента открыт другой CRM-task;
- есть активная коммуникация в последние 3 дня;
- недавно было коммерческое касание без ответа и не прошёл cooldown.

Waitlist (`P1`) может обходить обычный commercial cooldown, но не должен перебивать сервис, активную задачу или запрет на контакт.

## Канал и визуалы

- `CALL`: локальный ценный brand buyer, когда уместен быстрый звонок.
- `MESSAGE`: waitlist, неместный/неизвестная география, визуальный first-look, онлайн-подбор.

Если канал `MESSAGE` и у товара есть фото, в карточку задачи сразу прикладываются 3–5 визуалов. Продавец не спрашивает «хотите фото?» — фото показываются сразу.

## Отображение

Администратор видит задачи в разделе CRM и может сгенерировать вручную кнопкой «Сгенерировать новинки». В карточке задачи показываются бренд, магазин, канал, фото и позиции поступления.

Продавец видит только свои задачи в CRM-продавца. В карточке также отображаются фото/позиции новинок, скрипт и поле фиксации результата.

## Follow-up

Если продавец фиксирует результат и указывает будущую `next_action_date`, система создаёт отдельную follow-up задачу с `source = crm_followup` и ссылкой на исходную задачу в `source_payload.parent_task_id`.

## Атрибуция

Продажи после контакта считаются существующим CRM-механизмом атрибуции через `crm_tasks` и `customer_messages`. Для кампании «Новое поступление» отдельная таблица продаж не создаётся.

## Настройки окружения

- `CRM_COMMERCIAL_COOLDOWN_DAYS` — cooldown коммерческих касаний, по умолчанию 30 дней.
- `CRM_NEW_ARRIVAL_LOOKBACK_HOURS` — период поиска приходных событий для фонового запуска, по умолчанию 24 часа.
- `CRM_NEW_ARRIVAL_LIMIT_ARRIVALS` — максимум групп поступлений за запуск, по умолчанию 10.
- `CRM_NEW_ARRIVAL_LIMIT_CLIENTS_PER_ARRIVAL` — максимум клиентов на группу поступления, по умолчанию 25.
- `CRM_NEW_ARRIVAL_RECEIPT_SYNC_ENABLED` — включает синхронизацию первичных приходных накладных 1С перед генерацией задач, по умолчанию `true`.
- `CRM_NEW_ARRIVAL_RECEIPT_MAX_DOCUMENTS` — максимум приходных документов 1С за один запуск, по умолчанию 500.
- `ONEC_PURCHASE_RECEIPT_ENDPOINT` — OData endpoint документов прихода, по умолчанию `/Document_ПриходнаяНакладная`.
- `ONEC_PURCHASE_RECEIPT_LINES_ENDPOINT` — OData endpoint табличной части «Запасы», по умолчанию `/Document_ПриходнаяНакладная_Запасы`.
- `ONEC_MAIN_WAREHOUSE_ID` — `Ref_Key` основного склада, по которому определяется первичный приход ассортимента. Текущее значение GLAME: `e1a2eace-fdc8-11ef-8c0c-fa163e4cc04e`.

## Текущая реализация источника 1С

Сервис `/root/glame-platform/backend/app/services/onec_purchase_receipt_arrival_service.py` читает документы `Document_ПриходнаяНакладная` с видом операции `ПоступлениеОтПоставщика` и строки табличной части `Document_ПриходнаяНакладная_Запасы`.

Правило отбора строк:

1. Документ проведён и не помечен на удаление.
2. Дата документа попадает в окно генерации. Из-за особенностей 1С Fresh фильтр даты дополнительно проверяется локально в Python.
3. Строка относится к `ONEC_MAIN_WAREHOUSE_ID`, то есть к основному складу. Строки перемещений/наличия в магазинах не используются.
4. Номенклатура сопоставлена с товаром платформы по `Номенклатура_Key` или `Номенклатура_Key#Характеристика_Key`.
5. Товар проходит `is_analytics_eligible_product`: упаковка, пакеты, мешочки, коробки, салфетки, расходники, сертификаты и другие технические/сопутствующие позиции отсекаются.

Ручная кнопка «Сгенерировать новинки» и ночной scheduler используют один путь: сначала синхронизируют приходные накладные в `product_stock_arrival_events` с `source = onec_purchase_receipt`, затем `CrmNewArrivalService` создаёт задачи продавцам.

## Состояние запуска

Таблица событий прихода добавлена. Генератор будет создавать задачи только после появления корректных событий закупки/приходной накладной на основной склад. Синхронизация остатков и перемещения магазинов больше не пишут события «Новое поступление».

Исторический первый запуск кампании был создан до event-режима: 134 задачи на 2026-08-21. Чтобы они не мешали продавцам и аналитике активных задач, первая волна архивирована без удаления: задачи переведены в статус `not_relevant`, в историю добавлено событие `archived_initial_new_arrival_wave`.

Ручная генерация 253 задач после 15 августа 2026 была выполнена по старому fallback по остаткам/перемещениям. После уточнения бизнес-правила Елены эти задачи также архивированы без удаления: статус `not_relevant`, событие `archived_wrong_new_arrival_source`.

Аналитика эффективности кампании доступна в общем разделе «Аналитика кампаний»: можно отфильтровать кампанию «Новое поступление» и смотреть охват, контакты, покупки, выручку, каналы, продавцов и таблицу покупок в попапе результатов.
